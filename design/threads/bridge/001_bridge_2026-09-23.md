# 001 - bridge to mzLibR - 2026-09-23 - Every wire verb now has one YAML spec, and mzLibR's man pages render from it: act as if you had already agreed

**Decision (the maintainer's, 2026-09-23): adopted, effective now.** Please reply to confirm, and
from today act as if you had already agreed. This is the first message on this thread. The *bridge*
is the umbrella project above pyMzLib, mzLibRust and mzLibR. It owns the language-neutral wire
contract that all three bindings project.

## What changed

A large batch of mzLib work is about to be projected into all three bindings: 26 merged mzLib PRs
since 1.0.591. They include MetaMorpheus protein-group and peptide tables, mzIdentML, SDRF sample
informativeness and age parsing, and Ensembl and GO annotation. The documentation for it must be
**world class** and **the same in Python, Rust and R**.

An audit on 2026-09-23 found the three bindings already drifting apart:

- mzLibR's `man/` prose is hand-copied from pyMzLib docstrings, with nothing keeping it in step.
- There are zero `@examples`, no vignettes, no pkgdown site and no `NEWS.md`.
- `docs/name-parity.md` has no sdrf rows, and no CI runs `name-parity.R`.
- The `mzlib_*` condition classes have no man page.
- There is no per-verb contract anywhere.

So the facts about each wire verb now live in exactly one place: one YAML file per verb in the
bridge (`design/verbs/<module>.<verb>.yaml`). A spec records:

- params with **units** and valid ranges, and defaults
- result fields (your data.frame columns) with type, **unit**, **nullable (NA) and what NA means**
- error kinds (usage / service_unavailable / correctness) and when each happens
- caveats
- the mzLib symbols wrapped, at the pin
- DOIs for the science
- fixture-backed examples in all three languages
- `since` per binding

A checker validates each spec against the bridge's verb switch and the recorded fixtures. The pilot
is `readers read-spectra`. **Your binding keeps its idiom**: flattened snake_case names,
data.frames, and prose. The spec owns the facts; where a binding's docs disagree with the spec, the
binding is wrong.

## Asks

**SPEC-1 · A projected verb cites its spec.** Every verb you project from now on names its spec
file in the PR. Record the verb's `bindings.r` spelling (for example `readers_read_spectra`) and
its `since.mzlibr` version, and send both back to the bridge.

**SPEC-2 · Render and lint the man pages from the spec.** Use the shared reference-page order:
summary, wraps, params, returns, errors, caveats, executed example, performance, see also
(including the Python and Rust spellings), references, since.

- Have `scripts/build-man.R` inline the params, returns and errors tables from the spec as an
  `@section`, and enumerate every returned column with its unit and NA meaning. `@return` is one
  paragraph today.
- Extend `scripts/name-parity.R` to read the specs, check `@param` and `@return` text for units,
  and run in CI on PRs (`git diff --exit-code`).
- Move the man-drift check from `release.yml` to `ci.yml`.

**SPEC-3 · Examples run.**

- Add `@examples` that run against the spec's named fixtures through a fixture-replay stub bridge,
  so `R CMD check` executes them. Use `\donttest{}` only for network cases.
- Add a pkgdown site, and a `NEWS.md` whose entries use the spec's `since` versions.
- Add one vignette per module.

**SPEC-4 · Close the existing parity gaps and stale text before the batch.**

- `pride search` and `quant median-polish` are on the wire and in Python, but not in R.
- The `mzlib_*` condition classes need a man page (`?mzlib_error`).
- `test-readers.R:271` expects 14 viewless formats; the next repin makes that 17 of 36.
- About 12 sites still warn about mzLib#1111, including a runtime warning and a test asserting it.
  #1155 fixed it inside the current pin.
